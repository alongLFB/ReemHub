## 1. 文档目的

定义 ReemHub 首期的产品范围、角色、流程、业务规则和验收标准。技术实现、数据模型和部署方案见关联的技术架构设计。

## 2. 背景与问题

Reem 岛华人朋友在聚餐、生活互助时，反复遇到以下问题：

- 聚餐 AA 或代购后，需要在群聊中查找 IBAN、手机号并手工核算；
- 餐厅推荐随聊天记录流失，缺少可筛选、可复用的本地美食清单；
- 多人、多笔垫付且并非所有人参与每笔消费时，手工算账容易出错；
- 单一微信群无法妥善处理成员准入、资料可见范围和私密内容。

## 3. 产品定位、目标与非目标

### 3.1 产品定位

ReemHub 是面向小型生活社群的私密协作门户。用户可创建和加入多个圈子；每个圈子独立管理成员、资料可见性、美食推荐、活动和活动账本。

### 3.2 首期目标

1. 提供邮箱密码和 Google 两种安全登录方式。
2. 支持创建公开或私密圈子，并由圈子管理员审批入圈申请。
3. 让成员按圈子、按资料字段自主决定公开哪些个人资料，并提供一键全选。
4. 在圈子内提供群友录、餐厅推荐与随机选择、约饭报名和多笔 AA 结算。
5. 使圈内联系方式与 IBAN 的查看、复制和结算使用可控、可追溯。

### 3.3 非目标（首期）

- 不提供站内即时聊天、社交动态流或支付/代扣服务；
- 不接入银行 API，不替用户实际执行转账；
- 不做公开点评社区、广告或商家入驻；
- 不支持跨圈子合并活动、账本或自动同步成员资料；
- 不承诺债务化简结果是数学意义上的最少转账笔数。

## 4. 角色与术语

| 角色/术语 | 定义 |
| --- | --- |
| 注册用户 | 已完成邮箱验证或 Google 登录的 ReemHub 用户，尚不必然属于任何圈子。 |
| 圈子创建者 | 每个圈子的唯一 OWNER。创建时自动成为首位成员，可任命多位管理员、转让创建者身份或解散圈子。 |
| 圈子管理员 | 由创建者任命；可审批成员申请、配置圈子信息与邀请方式，但不能自行转让创建者身份或解散圈子。 |
| 圈子成员 | 已获批准加入某个圈子的用户。只能访问自己所属圈子的受保护内容。 |
| 申请人 | 已提交加入申请、等待管理员处理的注册用户。 |
| 公开圈子 | 在站内广场可被浏览、搜索和查看简介的圈子；未加入者只能查看简介并申请加入，不可访问圈内内容。 |
| 私密圈子 | 不出现在广场或搜索结果中；仅持有效邀请链接或邀请码的用户才可发起加入申请。 |
| 圈子资料可见性 | 成员针对某一圈子，逐字段决定其他已批准成员能否看到其资料。 |

## 5. 功能需求

### 5.1 账户、注册与登录

#### FR-AUTH-001 邮箱注册与登录

- 用户以邮箱和密码注册；注册成功前必须完成邮箱验证码验证。
- 支持邮箱加密码登录、密码找回和重置。
- 注册完成只建立平台账户，不自动加入任何圈子。

#### FR-AUTH-002 Google 快速登录与账户绑定

- 用户可使用 Google OAuth 2.0 登录或注册。
- Google 已验证邮箱与已有邮箱账户一致时，系统应安全绑定到原账户，不得生成重复账户。
- 已登录用户可在个人设置中绑定或解绑 Google 登录；解绑后必须保留至少一种可用登录方式。
- 首次 Google 登录可预填头像和显示名称，用户可在保存前修改。

### 5.2 个人资料与隐私控制

#### FR-PROFILE-001 基础资料

用户可维护以下资料：

| 字段 | 说明 |
| --- | --- |
| 显示名称 | 微信昵称或常用称呼。 |
| 头像 | Google 头像、上传头像或系统默认头像。 |
| 楼宇 | Reem 岛楼宇预设选项加自定义输入。 |
| 手机号 | 阿联酋手机号。 |
| 开户银行 | 如 ADCB、ENBD、FAB、Wio、Mashreq。 |
| IBAN | 阿联酋本地 IBAN，输入时校验 AE 开头和 23 位长度。 |
| 生日（月/日） | 不收集出生年份。 |

注册邮箱、认证提供方标识、密码及后台审计信息永不对圈子成员公开。

#### FR-PROFILE-002 按圈子字段授权

- 用户加入圈子后，在该圈子的“资料可见性”页面逐项开启或关闭上述资料字段。
- 提供“全部公开”快捷操作，并在提交前提示将公开的字段；用户仍可逐项取消。
- 可见性以“用户 × 圈子 × 字段”为边界：加入 A 圈子的选择不得自动应用到 B 圈子。
- 只有同圈且已获批准的成员，才可查看对方明确公开的字段；未公开字段显示为“未公开”。
- 用户变更可见性后，应立即影响后续查看和复制权限。

### 5.3 圈子

#### FR-CIRCLE-001 创建圈子

- 任意注册用户可创建圈子，填写名称、简介、封面/头像、可见性（公开或私密）与可选标签。
- 创建者自动成为唯一创建者（OWNER）和首位成员。
- 管理员可编辑圈子介绍、可见性和邀请设置。
- 创建者可任命或撤销多位管理员；管理员名单应向圈内成员展示。

#### FR-CIRCLE-002 广场与发现

- 广场仅展示公开圈子的名称、简介、封面、标签、创建者展示名和成员数；不展示成员资料、餐厅、活动、账本或私密圈子存在信息。
- 用户可按名称和标签搜索公开圈子。
- 公开圈子的详情页提供“申请加入”入口；提交申请后进入待审批状态。

#### FR-CIRCLE-003 私密圈子与邀请

- 私密圈子不出现在广场、搜索结果或未获邀请用户的任何列表中。
- OWNER/ADMIN 创建邀请链接或邀请码时，可自行设置有效期和最大使用次数，并可撤销任意邀请。
- 所有 ACTIVE 成员也可创建邀请链接或邀请码；成员只能撤销自己创建的邀请。
- 受邀用户登录后可凭其中任一方式访问圈子简介并提交加入申请。接受邀请等同于提交入圈申请，不直接加入圈子。
- 有效邀请仅授予“提交申请和查看最小圈子简介”的资格，不绕过管理员审批。
- 管理员审批时可看到申请使用的邀请及邀请创建人，便于判断来源。
- 已加入的成员可在“我的圈子”中看到所属公开和私密圈子。

#### FR-CIRCLE-004 成员审批与成员状态

- 圈子管理员可批准或拒绝申请；申请人应看到当前状态和处理结果。
- 获批准后，用户成为成员，才能访问成员目录、圈内餐厅、活动与账本。
- 管理员可移除成员；被移除用户立即失去该圈子的内容和资料访问权限。
- 成员主动退出或被移除后，可按公开圈子申请或私密圈子有效邀请的正常流程再次提交申请；每次重新加入均须 OWNER/ADMIN 批准。
- 退出或被移除不删除其历史活动报名、AA 账单参与、支出、分摊、结算和名单调整记录；该用户在非 ACTIVE 期间不得访问这些圈内历史内容。
- 退出或被移除时，系统立即撤销该圈子的资料字段可见性。重新获批后，用户须重新设置向该圈子公开的资料字段。
- 创建者可将创建者身份转让给一位当前圈子成员；转让后，原创建者可保留管理员身份或退出圈子。
- 创建者退出前必须选择转让创建者身份或解散圈子，不能使圈子处于无创建者状态。
- 创建者可解散圈子。解散须经过二次确认，并选择“立即彻底删除”或“保留 7 天”。
- 立即彻底删除会移除圈子及其成员关系、邀请、资料可见性、餐厅、活动、AA 账单、结算和圈子级审计记录；所有成员的 ReemHub 平台账户保留。
- 选择保留 7 天时，圈子立即关闭访问并撤销邀请；创建者可在 7 天内恢复圈子。到期后系统自动按彻底删除处理。

### 5.4 群友录与转账助手

- 成员目录只展示当前圈子的批准成员，支持按显示名称、楼宇和银行筛选。
- 卡片展示所有者对当前圈子已公开的头像、显示名称、楼宇、银行及其他字段。
- “本月寿星”仅从本圈明确公开生日的成员中计算和展示。
- 仅在所有者公开对应字段时，展示“复制手机号”或“复制 IBAN”按钮。
- IBAN 以每四位分组显示；复制时复制无空格的标准化值并显示成功提示。

### 5.5 美食指南

- 餐厅记录归属一个圈子，包含名称（中/英文）、菜系、区域、人均 AED 区间、Google Maps 链接、招牌菜、提示和推荐人。
- 圈内成员可按区域、菜系和预算筛选。
- “今天吃什么”从当前筛选结果中随机选择一家餐厅，并可直接带入“发起约饭”的餐厅字段。
- 所有已批准成员均可创建餐厅推荐。
- 新建餐厅推荐保存后立即在本圈可见，不需要管理员审核。
- 该餐厅推荐的创建者，以及圈子创建者或管理员，均可编辑、删除该记录。
- 首期不要求自动识别或合并重复餐厅。

### 5.6 约饭活动与 AA 账本

#### FR-EVENT-001 活动与报名

- 圈内成员可创建活动，填写标题、时间、关联餐厅或自定义地点、备注，并可选设置人数上限、报名截止时间和候补名单。
- 人数上限可不设置，表示不限人数；候补名单只在设置人数上限时可开启。
- 在报名截止前，成员可报名或取消报名，并看到参与者和候补名单。满员且候补开启时，新报名者按进入候补名单的时间顺序排队。
- 有参与者取消后，最早进入候补名单的成员自动转正，并收到站内通知和邮件。
- 所有已批准成员均可创建活动；活动创建者，以及圈子创建者或管理员，均可编辑、删除活动。
- 活动创建者、圈子 OWNER/ADMIN 可在任何时间手动调整参与者和候补名单；每次调整须记录操作者、时间、调整前后状态和可选的调整理由，并通知受影响成员。
- 活动状态至少包括开放报名、已关闭和已取消。关联或独立 AA 账单单独维护其结算状态；活动创建者或管理员可提前关闭报名。

#### FR-EVENT-002 活动提醒与通知偏好

- 活动创建者可在创建时设置一个或多个“活动开始前多久提醒”的时间点，并可在创建后编辑提醒设置。
- 活动时间或提醒设置变更后，系统取消旧的未发送提醒并按最新设置重新安排。
- 对处于参与者状态的圈内成员，活动提醒始终生成站内通知。
- 用户可在通知设置中关闭活动提醒邮件；邮箱验证、密码重置等认证必需邮件不受此设置影响。
- 用户可接入自己的 Telegram Bot：填写 Bot Token 与 Telegram Chat ID，并在连通性测试成功后启用 Telegram 活动提醒。

#### FR-BILL-001 活动关联与独立 AA 账单

- 圈内成员可为一个活动创建关联 AA 账单；AA 账单创建者是唯一可编辑该账单支出、参与者和分摊方式的人。
- 圈内成员也可不创建活动，直接在圈子内新建独立 AA 账单，用于临时线下聚餐、代购或其他共同支出。
- 新建账单时可从当前圈子的 ACTIVE 成员中快速多选参与者，也可手动添加仅属于该账单的临时 Guest，并填写其显示名称。
- Guest 不会创建平台账户，不加入圈子，不出现在成员目录，不接收站内/邮件通知，也不能访问账单；其名称仅在该账单及其结算记录中显示。

#### FR-BILL-002 多笔支出与分摊

- 一个 AA 账单可记录多笔支出，每笔包含名称、付款人、金额（AED）和分摊参与者。付款人及分摊参与者均可为圈内成员或该账单的 Guest。
- 活动关联账单默认带入已报名成员；账单创建者可按实际消费调整，并可添加 Guest。
- 每笔支出可独立选择以下分摊方式：

| 方式 | 用户输入 | 示例：300 AED 由 A、B、C 分摊 |
| --- | --- | --- |
| 均分 | 选择分摊成员 | 三人各 100 AED。 |
| 不等额 | 为每人填写金额 | A/B/C 分别为 150/100/50 AED。 |
| 按比例 | 为每人填写百分比 | 50%/30%/20%，分别为 150/90/60 AED。 |
| 按份数 | 为每人填写正整数份数 | 2/2/1 份，共 5 份，分别为 120/120/60 AED。 |

- 不等额的金额之和必须等于账单总额；百分比之和必须等于 100%；份数必须均为正整数。
- 每笔分摊金额以 AED 两位小数落库。均分、百分比或份数出现尾差时，系统按确定的尾差分配规则处理，并在提交前展示最终每人金额。
- 账单创建者负责录入、修改和删除支出，以及确定每笔消费的分摊参与者和分摊方式；OWNER/ADMIN 不覆盖该账单编辑权限。

#### FR-BILL-003 结算与转账标记

- 系统按“总垫付 − 总应摊”计算每位参与者净额，并生成债务化简后的转账建议。
- 每条建议显示付款人、收款人和 AED 金额。收款人为圈内成员时，仅在其对当前圈子公开时可复制 IBAN/手机号；Guest 不提供联系方式复制。
- 圈内成员付款人可将自己的转账建议标记为“已转账”；Guest 相关转账由账单创建者代为标记。该标记只表示线下操作确认，不代表平台验证了银行交易。
- 所有建议完成后，账单创建者可将账单标记为已结算。

### 5.7 站内与邮件通知

- 首期同时提供站内通知中心和 SMTP 邮件通知。站内通知支持未读状态和跳转至对应对象。
- 以下关键事件必须生成站内通知并发送邮件：

| 事件 | 收件人 |
| --- | --- |
| 提交入圈申请 | 该圈子的 OWNER 和 ADMIN。 |
| 申请获批或被拒绝 | 申请人。 |
| 成员被移除或圈子被解散 | 受影响成员。 |
| 活动报名或取消报名 | 活动创建者。 |
| 候补自动转正或人工调整名单 | 被调整成员；候补自动转正时另通知活动创建者。 |
| 活动开始前提醒 | 当前参与者；站内必达，邮件和 Telegram 受个人通知设置控制。 |
| 结算建议生成或重新生成 | 账单中的圈内成员参与者；Guest 不接收通知。 |
| 某笔转账被标记为已转账 | 对应收款人。 |

- 邮箱验证和密码重置邮件属于认证必需邮件，不受通知偏好影响。
- 站内通知和邮件的内容不得包含完整 IBAN、手机号或其他未获授权的资料字段。

## 6. 核心流程

### 6.1 注册并入圈

1. 用户通过邮箱验证注册，或通过 Google 登录建立账户。
2. 用户在广场发现公开圈子，或打开私密圈子的邀请链接/输入邀请码。
3. 用户提交加入申请。
4. 圈子管理员批准或拒绝。
5. 批准后，用户设置该圈子的资料可见性，并进入圈子主页。

### 6.2 创建并管理圈子

1. 注册用户创建圈子并选择公开或私密。
2. 系统将创建者设为管理员和成员。
3. 管理员配置简介、可见性、邀请链接/邀请码。
4. 管理员处理加入申请，并可在必要时移除成员。

### 6.3 活动结算

1. 圈内成员发起活动，其他成员报名。
2. 活动期间或结束后录入每笔消费及其分摊成员。
3. 系统计算净额并输出转账建议。
4. 付款人复制已公开的收款信息，在站外完成转账并手动标记。
5. 确认完成后，将活动账本结算归档。

## 7. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 平台账户和圈子成员资格分离；登录成功不等于可访问任何圈子。 |
| BR-002 | 圈子是资料、成员、餐厅、活动和账本的强隔离边界。任何跨圈查询均须拒绝。 |
| BR-003 | 公开圈子的未加入用户只能查看圈子简介并提交申请；成员目录、餐厅、活动和账本均需有效成员资格。 |
| BR-004 | 私密圈子的存在和内容均不得出现在未获邀请用户的搜索、广场和错误提示中。 |
| BR-005 | 邀请链接或邀请码不能替代管理员审批。管理员撤销后，未使用邀请立即失效。 |
| BR-006 | 资料字段默认不公开，且必须由资料所有者在每个圈子中显式选择公开。 |
| BR-007 | 手机号、IBAN 和生日属于敏感资料；查看和复制前必须在服务端复核成员资格和字段授权。 |
| BR-008 | 金额统一使用 AED，以两位小数处理；单笔支出分摊之和必须等于支出总额。 |
| BR-009 | 已结算账单仅可由账单创建者恢复为可编辑状态；任何编辑均保留审计记录，并使旧结算建议失效后重新计算。 |
| BR-010 | 每个活跃圈子必须恰有一位创建者。创建者退出前必须完成身份转让或解散圈子。 |
| BR-011 | 解散圈子须由创建者二次确认，并选择立即彻底删除或保留 7 天；两种模式均立即撤销邀请并关闭圈内资源访问。 |
| BR-012 | 所有 ACTIVE 成员可创建餐厅推荐和活动；各自内容的创建者与圈子 OWNER/ADMIN 可编辑、删除该内容。 |
| BR-013 | 每笔支出独立选择均分、不等额、按比例或按份数分摊；服务端校验输入规则并保证最终分摊之和等于账单总额。 |
| BR-014 | 关键业务事件须创建站内通知并异步发送 SMTP 邮件；邮件失败不得回滚审批、报名、结算等已完成的业务操作。 |
| BR-015 | 活动人数上限、报名截止时间和候补名单均由活动创建者可选配置；候补名单仅在有人数上限时可用。 |
| BR-016 | 账单可独立存在或关联一场活动。账单创建者独占账目、参与者和分摊的编辑权；Guest 仅是账单参与者，不具备平台或圈子身份。 |
| BR-017 | 候补成员按进入候补名单的时间先后自动转正；活动创建者、OWNER/ADMIN 可在任何时间手动调整参与者或候补名单。 |
| BR-018 | 自动或手动名单调整均须留存调整记录；手动调整理由可选填，受影响成员须收到站内和邮件通知。 |
| BR-019 | LEFT 或 REMOVED 用户可重新申请加入，但必须再次获得 OWNER/ADMIN 批准；退出或移除不会删除圈内历史活动和账单记录。 |
| BR-020 | 用户退出或被移除时，立即撤销其在该圈子的所有资料字段可见性；再次获批后须重新授权。 |
| BR-021 | ACTIVE 成员创建的餐厅推荐保存后立即在本圈可见；不设审核流程，内容创建者与 OWNER/ADMIN 可编辑、删除。 |
| BR-022 | OWNER/ADMIN 可自行设置其创建邀请的有效期和最大使用次数；ACTIVE 成员可创建邀请，但受邀者均须提交申请并经 OWNER/ADMIN 批准。 |
| BR-023 | AA 账单仅由其创建者编辑、删除、重新开启和结算；修改后须使旧结算建议失效并保留审计记录。 |
| BR-024 | 活动创建者可创建后编辑一个或多个提醒时间点；活动提醒的站内通知不可关闭，邮件和 Telegram 提醒由用户自行选择。 |

## 8. 非功能需求

- 移动端优先，适配微信内置浏览器和常见手机屏幕。
- 受保护页面和 API 均需在服务端进行身份、圈子成员资格和权限校验。
- 对密码、会话、IBAN、邀请令牌和操作日志采取相应安全保护；详见技术架构设计。
- 中文为首期界面语言；文本结构保留未来国际化扩展能力。
- 常用列表、筛选、申请和记账操作应有明确的加载、成功与失败反馈。

## 9. 验收标准

| 编号 | 验收标准 |
| --- | --- |
| AC-001 | 用户可完成邮箱验证注册、密码登录、密码重置和 Google 登录；同一已验证邮箱不会产生重复账户。 |
| AC-002 | 注册用户可创建公开或私密圈子，创建者自动成为管理员。 |
| AC-003 | 公开圈子可在广场搜索和申请加入；私密圈子仅能经有效邀请链接或邀请码进入申请入口。 |
| AC-004 | 任何加入申请均须管理员批准后，申请人才能访问圈内受保护内容。 |
| AC-005 | 创建者可任命多位管理员，且管理员可完成获授权的审批和邀请管理操作。 |
| AC-006 | 创建者只能将创建者身份转让给当前成员；创建者退出前必须完成转让或解散。 |
| AC-007 | 解散圈子须二次确认，并可选择立即彻底删除或保留 7 天；两种模式均使邀请失效且圈内内容不可访问。 |
| AC-008 | 选择保留 7 天的已解散圈子可由原创建者在到期前恢复；过期后自动彻底删除。 |
| AC-009 | 成员可逐字段设置本圈资料可见性，可一键全选；未公开字段不出现在页面或 API 返回中。 |
| AC-010 | 圈内成员目录、餐厅、活动和账本不能被其他圈子成员访问。 |
| AC-011 | 仅资料所有者公开手机号或 IBAN 后，同圈成员才能查看与复制该字段。 |
| AC-012 | 所有 ACTIVE 成员可创建餐厅推荐和活动；内容创建者与 OWNER/ADMIN 可编辑、删除对应内容。 |
| AC-013 | 活动创建者可选设置人数上限、报名截止时间和候补名单；满员后新报名者按顺序进入已开启的候补名单。 |
| AC-014 | 有人取消后，最早候补成员自动转正，并收到站内和邮件通知。 |
| AC-015 | 活动创建者、OWNER/ADMIN 可随时调整参与者和候补名单；系统记录调整前后状态、操作者、时间及可选理由。 |
| AC-016 | 圈内成员可新建不关联活动的独立 AA 账单，并快速多选成员或添加仅属于该账单的 Guest。 |
| AC-017 | 账单创建者可维护支出和分摊；Guest 不会获得账户、成员目录可见性或通知。 |
| AC-018 | 每笔支出均可选择均分、不等额、按比例或按份数；系统拒绝总额、比例或份数不合法的数据。 |
| AC-019 | 系统结算金额与各支出、分摊明细一致，所有转账建议金额的净效应等于每人净额。 |
| AC-020 | 已结算账单不能被普通成员静默修改，关键操作可追溯。 |
| AC-021 | 入圈审批、成员移除、活动报名、结算和转账标记等关键事件会生成站内通知并发送邮件；邮件失败不会影响业务结果。 |
| AC-022 | 已退出或被移除用户可再次申请，且在管理员重新批准前不能访问圈内内容。 |
| AC-023 | 成员离开后历史活动和 AA 账单记录仍保留，且其原有资料字段不会因历史记录或重新加入而自动重新公开。 |
| AC-024 | ACTIVE 成员新建的餐厅推荐无需审核即在本圈展示，且内容创建者与 OWNER/ADMIN 均可编辑、删除。 |
| AC-025 | OWNER/ADMIN 可设置邀请有效期和使用次数；成员创建的邀请被接受后仅产生待审批申请，不会直接授予圈子访问权限。 |
| AC-026 | 仅 AA 账单创建者可编辑、删除、重新开启或结算账单；圈子 OWNER/ADMIN 不可越权编辑，修改后生成新的结算建议。 |
| AC-027 | 活动创建者可设置和修改活动开始前的提醒；活动时间变更后，旧提醒不再发送。 |
| AC-028 | 用户可关闭活动提醒邮件，或配置自己的 Telegram Bot Token 与 Chat ID 接收 Telegram 提醒；站内提醒仍会生成。 |
